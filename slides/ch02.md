# 2.1 数据模型与关系模型

## 关系模型的三要素
| 要素 | 说的是什么 |
|---|---|
| 数据结构 | 数据一律存成二维表 |
| 关系操作 | 选择、投影、连接，SQL 是实现 |
| 完整性约束 | 数据必须满足的规则 |

::: notes
数据模型是对现实世界数据特征的抽象。关系模型 1970 年由科德提出，最大的优点是简单：不管什么数据都放进表格。
:::

# 2.2 关系的基本术语

## 表、行、列的“学名”
| 学名 | 日常说法 | 小店里的例子 |
|---|---|---|
| **关系** | 表 | 商品表 product |
| **元组** | 行、记录 | 燕麦片那一行 |
| **属性** | 列、字段 | price 这一列 |
| **域** | 取值范围 | 性别 {男, 女} |
| **关系模式** | 表结构 | product(product_id, name, …) |

## 成为“关系”的条件
- 每格只放**一个不可再分**的值
- 列名**不能重复**
- 任意两行**不能完全相同**
- 行、列的**顺序无关紧要**

# 2.3 键：用什么来找到一行

## 超键、候选键、主键
- **超键**：能唯一确定一行的列组合
- **候选键**：去掉任何一列就不行的超键
- **主键**：从候选键里选一个
  - 不能重复，也不能为空
- 几列合起来做主键：**复合主键**

## 复合主键的例子：订单明细
| order_id | product_id | quantity | unit_price |
|---|---|---|---|
| 1 | 33 | 1 | 4.50 |
| 1 | 34 | 1 | 6.50 |
| 1 | 35 | 3 | 4.00 |

::: notes
单看 order_id 会重复，单看 product_id 也会重复，(order_id, product_id) 合起来才唯一。组成候选键的列叫主属性，其余叫非主属性，第 7 章判断范式要用到。
:::

## 外键：把表连起来
!mermaid 1
- 订单表的 customer_id **参照**顾客表的主键
- 被参照的表 / 参照的表
- 列名可以不同，**含义和类型要相同**

# 2.4 完整性约束

## 三类完整性
| 类别 | 规则 | 违反的例子 |
|---|---|---|
| **实体完整性** | 主键不空、不重复 | 两个 1 号顾客 |
| **参照完整性** | 外键为空或等于已有主键 | 订单写着顾客 999 |
| **用户定义完整性** | 业务规则 | 价格填了 -5 |

## 数据库怎样把关
- 违反实体完整性：**1062 / 1048** 报错
- 外键指向不存在的行：**1452** 报错
- 删除还被引用的行：**1451** 拒绝
- 违反检查约束：**3819** 报错

::: notes
这些报错实验 2-2 会一一触发。报错不是坏事，是数据库在替我们把关。
:::

# 2.5 关系运算

## 选择与投影
- **选择** σ：按条件挑**行**（横着切）
- **投影** π：挑**列**并去重（竖着切）
- 价格不超过 5 元的商品 → 选择
- 只看名称和价格 → 投影

## 连接
| 商品 name | 类别 name |
|---|---|
| 无糖绿茶 500ml | 饮料 |
| 生菜 300g | 生鲜果蔬 |
| 豆腐 400g | 生鲜果蔬 |
| 食盐 400g | 调味品 |

::: notes
连接按条件把两张表拼起来。按外键等于主键的连接叫等值连接，去掉重复列后叫自然连接。上表就是商品表和类别表按 category_id 连接后的投影。
:::

## 运算与 SQL 对照
| 运算 | 符号 | 对应的 SQL |
|---|---|---|
| 选择 | σ | `WHERE` |
| 投影 | π | `SELECT DISTINCT 列` |
| 连接 | ⋈ | `JOIN … ON` |
| 并 | ∪ | `UNION` |
| 差 | − | `NOT EXISTS`、`NOT IN` |
| 笛卡尔积 | × | `CROSS JOIN` |

## 前沿视窗：关系模型为什么还是主流
- **简单统一**：什么都放进表格
- **数据和程序分离**
- **数学基础扎实**，便于优化
- 50 多年，一直在吸收新技术
