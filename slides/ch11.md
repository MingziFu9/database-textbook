# 11.1 程序怎样访问数据库

## 驱动、连接与游标
!mermaid 1
- **驱动**：PyMySQL（MySQL）、psycopg2（PostgreSQL）
- **连接**：程序和服务器之间的“电话线”
- **游标**：执行 SQL、取结果

::: notes
Python 为数据库驱动定了统一接口规范 PEP 249，换一种数据库写法几乎一样。游标可以想成 DBeaver 里的一个 SQL 编辑窗口：execute 是点“运行”，fetchone 取一行，fetchall 取全部。
:::

## 第一个程序：查商品
```python
import pymysql

conn = pymysql.connect(host="127.0.0.1", port=3306, user="shopapp",
                       password="App#2026", database="shop",
                       charset="utf8mb4")              # ① 连接
cur = conn.cursor()                                   # ② 游标
cur.execute("SELECT COUNT(*) FROM product")           # ③ 执行
print("商品总数：", cur.fetchone()[0])                 # ④ 取结果 → 48
cur.close()                                           # ⑤ 关闭
conn.close()
```

::: notes
运行前先用 root 执行 lab11_0_setup.sql，建程序专用账号 shopapp，程序不用 root。charset="utf8mb4" 不能少，否则中文变问号。DECIMAL 到 Python 里是 Decimal 对象，算钱比浮点数准确。
:::

# 11.2 参数化查询：堵住 SQL 注入

## 两种写法的对比
```python
text = "' OR '1'='1"                                # 攻击者的输入
# ✗ 拼接：输入成了 SQL 的一部分
sql = "SELECT customer_id, name FROM customer WHERE phone = '" + text + "'"
cur.execute(sql)                                    # 查到 200 行
# ✓ 参数化：%s 占位，输入单独传入
cur.execute("SELECT customer_id, name FROM customer WHERE phone = %s",
            (text,))                                # 查到 0 行
```

::: notes
编者实测：正常输入 10054751779 时两种写法都查到 1 行；输入注入串时拼接写法查到 200 行，参数化写法 0 行。PyMySQL 把输入里的单引号转义成 \'，整个输入只是一个普通的字符串值。
:::

## 参数化查询的写法规则
| 规则 | 正确 | 错误 |
|---|---|---|
| 占位符一律 `%s` | `price < %s` | `price < %d` |
| 占位符外**不加引号** | `name = %s` | `name = '%s'` |
| 参数作为第二个参数 | `execute(sql, (8,))` | `execute(sql % (8,))` |
| 通配符写在参数里 | `LIKE %s`，参数 `"%牛奶%"` | `LIKE '%%s%'` |
| 只能代替“值” | `stock < %s` | `FROM %s` |

## 增删改要提交
```python
with get_connection() as conn:
    with conn.cursor() as cur:
        cur.execute("UPDATE product SET stock = stock + %s "
                    "WHERE product_id = %s", (20, 5))
        print("影响行数：", cur.rowcount)
    conn.commit()            # 不写这一句，进货就白录了
```
- PyMySQL 默认**关闭自动提交**
- `cur.lastrowid`：新插入行的自增编号

## 用事务完成下单
```python
try:
    with conn.cursor() as cur:
        # 插订单 → 逐个商品：FOR UPDATE 读库存
        #   库存不够就 raise；够就插明细、扣库存
        ...
    conn.commit()            # 全部成功才提交
except Exception:
    conn.rollback()          # 任何一步出错都回滚
    raise
finally:
    conn.close()
```

完整代码见正文 11.3.3 的 place_order 函数。编者实测：下单前燕麦片 91、挂面 0；先买 2 袋燕麦片成功，订单 2502，燕麦片 89；再在同一单里买 1 袋燕麦片和 1 包挂面，挂面不够，整单回滚，燕麦片仍是 89，没有被白扣。
:::

# 11.4 pandas 读写数据库

## read_sql 与 to_sql
```python
import pandas as pd
from sqlalchemy import create_engine

engine = create_engine("mysql+pymysql://shopapp:App%232026"
                       "@127.0.0.1:3306/shop?charset=utf8mb4")
df = pd.read_sql("SELECT name, price, stock FROM product "
                 "WHERE stock < 10", engine)
with engine.begin() as conn:          # 成功自动提交，出错自动回滚
    df.to_sql("monthly_report", conn, if_exists="append", index=False)
```

::: notes
read_sql 访问 MySQL 要用 SQLAlchemy 引擎；连接串里口令的 # 要写成 %23。SQL 里的 % 要写成 %%，例如 DATE_FORMAT(t, '%%Y-%%m')，否则报 unsupported format character。shopapp 没有建表权限，所以 monthly_report 表事先用 root 建好，程序里用 append，这也是最小权限原则。
:::

# 11.5 数据挖掘入门：窗口函数

## 窗口函数：分组但不合并行
```sql
函数名() OVER (PARTITION BY 分组列 ORDER BY 排序列)
```
- `OVER`：这是一个窗口函数
- `PARTITION BY`：分组，但**不合并行**
- `ORDER BY`：窗口里按什么顺序算
- GROUP BY 每组只剩一行，窗口函数每行都留着

## 三种排名
| 函数 | 并列时 | 库存 0, 0, 8, 8, 8, 13 |
|---|---|---|
| ROW_NUMBER | 不并列，顺序编号 | 1, 2, 3, 4, 5, 6 |
| RANK | 同名次，后面**跳号** | 1, 1, 3, 3, 3, 6 |
| DENSE_RANK | 同名次，**不跳号** | 1, 1, 2, 2, 2, 3 |

::: notes
例子是库存不足 20 件的商品按库存排名：挂面 0、橙汁 0、薯片 8、苹果 8、火锅底料 8、保鲜膜 13。RANK() OVER (PARTITION BY category_id ORDER BY price DESC) 可以在每个类别内部各自排名。每组取前 N 条：先用 ROW_NUMBER 编号，再在外层 WHERE rn <= N。
:::

## 累计与环比：SUM() OVER 与 LAG
| 月份 | 销售额 | 累计 | 上月 |
|---|---|---|---|
| 2026-01 | 10125.50 | 10125.50 | NULL |
| 2026-02 | 10021.40 | 20146.90 | 10125.50 |
| 2026-03 | 11238.70 | 31385.60 | 10021.40 |
| 2026-04 | 9989.30 | 41374.90 | 11238.70 |

- `SUM(…) OVER (ORDER BY 月份)`：累计
- `LAG(…)`：取上一行，算环比
