# 12.3 怎样比较两个向量

## 三种度量：以问题 q 和燕麦片 o 为例
| 度量 | 算法 | 结果 | 越相似时 |
|---|---|---|---|
| **内积** | 对应相乘再相加 | 1.53 | 越大 |
| **欧氏距离** | 相减、平方、相加、开方 | 0.1 | 越小 |
| **余弦相似度** | 内积 ÷ 两个长度之积 | 0.9983 | 越接近 1 |

::: notes
q = [0.9, 0.9, 0, 0]，o = [0.9, 0.8, 0, 0]。内积 0.81 + 0.72 = 1.53；欧氏距离 √0.01 = 0.1；|q| ≈ 1.2728，|o| ≈ 1.2042，余弦 1.53 ÷ (1.2728 × 1.2042) ≈ 0.9983。问题和薯片 [0, 0, 0.9, 0] 的内积、余弦都是 0，毫不相关。向量库常用余弦距离 = 1 − 余弦相似度，三种都变成“越小越近”。
:::

## 哪种用在哪里
| 度量 | 含义 | 常见用途 |
|---|---|---|
| **余弦相似度** | 方向是否一致 | 文本语义搜索，最常用 |
| **欧氏距离** | 两点的直线距离 | 图像、位置等 |
| **内积** | 方向和长度都考虑 | 推荐系统 |

- 向量已归一化（长度为 1）时，三种排出的顺序一样

# 12.4 为什么需要专门的向量数据库

## 逐个比较太慢，B+ 树帮不上忙
- 上亿件商品，每次搜索都和全部向量算一遍
- B+ 树只会“大于、小于、等于”，**一维有序**
- 几百维空间里找邻居，要新的**向量索引**
- **近似最近邻（ANN）**：用一点准确换很多速度
- **召回率**：返回的 10 个里有几个真是前 10 名

## 两种向量索引
- **IVF**：先分簇，只在最近的几个簇里找
  - 像先找书架，再在书架上一本本看
- **HNSW**：分层“邻居网”，上层大步跳，下层细找
  - 像先坐飞机，再坐地铁，最后步行找门牌

## 动手：HNSW 分层搜索
!sim hnsw-search
- 看查询在三层图上的路线
- 调大候选数 ef_search
- 比较次数增加，更容易找到真正的最近邻

## 召回率与速度的权衡（编者实测）
| 方法 | 20 次查询总耗时 | 召回率 |
|---|---|---|
| 逐个比较（精确） | 591.5 毫秒 | 100% |
| HNSW，ef_search = 10 | 11.1 毫秒 | 72.0% |
| HNSW，ef_search = 40（默认） | 12.9 毫秒 | 85.0% |
| HNSW，ef_search = 100 | 58.5 毫秒 | 100.0% |

::: notes
PostgreSQL 17 + pgvector 0.8.7，10 万条 128 维向量，20 个查询各找最近的 10 个，建 HNSW 索引约 20.5 秒。结论：用索引快 10 到 50 倍；ef_search 调大，召回率上升、速度下降。商品推荐可以选快的，法律、医疗检索选准的。你的机器上耗时会不同，但规律一样。
:::

# 12.5 向量数据库的基本操作

## 和关系数据库对照
| 关系数据库（MySQL） | 向量数据库（Chroma） |
|---|---|
| 表 | 集合（collection） |
| 行 | 编号 + 向量 + 原文 + 元数据 |
| `INSERT` | `add()` |
| `WHERE price <= 16` | `where={"price": {"$lte": 16}}` |
| `ORDER BY … LIMIT 3` | `n_results=3` |
| B+ 树索引，结果精确 | HNSW 索引，**结果近似** |

## Chroma：专用向量数据库
```python
import chromadb
client = chromadb.Client()
col = client.create_collection(name="shop_demo",
          configuration={"hnsw": {"space": "cosine"}})
col.add(ids=["7", "8", "10"],
        embeddings=[[0.9, 1.0, 0, 0], [0.9, 0.8, 0, 0], [0.7, 0.9, 0, 0]],
        documents=["小米 1kg", "燕麦片 1kg", "芝麻糊 600g"],
        metadatas=[{"price": 15.80}, {"price": 26.90}, {"price": 18.80}])
res = col.query(query_embeddings=[[0.9, 0.9, 0, 0]], n_results=3,
                where={"price": {"$lte": 16}})
```

::: notes
编者用 11 种教学商品实测：最相近的 3 个是小米（余弦距离 0.0014）、燕麦片（0.0017）、芝麻糊（0.0077）；加上售价不超过 16 元，变成小米、全麦面包（0.0150）、鲜肉包（0.0256）。真正使用时把 embeddings= 换成 documents=，交给嵌入模型自动算向量。
:::

## pgvector：向量就是一列
```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE product_vec (product_id INT PRIMARY KEY, name VARCHAR(40),
                          price DECIMAL(8,2), embedding vector(4));
SELECT name, price FROM product_vec
WHERE price <= 16
ORDER BY embedding <=> '[0.9, 0.9, 0, 0]'     -- 余弦距离
LIMIT 3;                                       -- 小米、全麦面包、鲜肉包
CREATE INDEX ON product_vec USING hnsw (embedding vector_cosine_ops);
```
- `<=>` 余弦距离，`<->` 欧氏距离，`<#>` 负内积

::: notes
和 Chroma 的结果完全一致。pgvector 最大的好处：向量和订单、库存、会员在同一个库里，能在一条 SQL 里连接、过滤、做事务，备份恢复照第 10 章做。
:::

# 12.6 产品版图与选择

## 向量数据库的几类产品
| 类型 | 代表产品 | 适合 |
|---|---|---|
| 专用向量数据库 | **Milvus**（国产开源）、Qdrant、Weaviate | 规模大、要分布式 |
| 关系数据库扩展 | PostgreSQL + pgvector | 已有关系库、规模中等 |
| 搜索引擎扩展 | Elasticsearch、OpenSearch | 需要混合检索 |
| 云服务 | 阿里云、腾讯云、华为云 | 不想自己运维 |
| 轻量库 | Chroma、Faiss | 学习、原型、小应用 |

# 12.8 局限与安全

## 用向量数据库要注意
- **嵌入模型决定效果上限**；换模型要全部重算
- 结果是近似的，总会返回 K 个，要设**相似度门槛**
- **权限不能丢**：入库带“谁能看”，检索按身份过滤
- **隐私**：有时能从向量还原出部分原文

## 前沿视窗：智能体的“长期记忆”
- 把值得记住的对话做成嵌入，存进向量库
- 下次对话先检索相关记忆，再交给大模型
- 存什么、存多久、怎样“忘掉我”
- 不同用户的记忆怎样隔离
