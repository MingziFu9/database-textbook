## 情景导入：答案分散在几张表里
- “每笔订单买了哪些商品？”
- 订单在 orders，商品名在 product
- 明细在 order_item
- 要把表**连起来**才能回答

# 5.1 为什么要连接

## 忘写连接条件：笛卡尔积
| name | category_id | category_id | name |
|---|---|---|---|
| 东北大米 5kg | 1 | 1 | 粮油米面 |
| 东北大米 5kg | 1 | 2 | 早餐冲饮 |
| 东北大米 5kg | 1 | 3 | 休闲零食 |
| 东北大米 5kg | 1 | 4 | 饮料 |

::: notes
48 种商品 × 8 个类别 = 384 行，每种商品和每个类别都配了一遍。连接一定要写连接条件。表名长时用表别名：FROM product p JOIN category c。
:::

# 5.2 内连接

## 两表和多表连接
```sql
SELECT p.name AS 商品, c.name AS 类别, p.price
FROM product p
JOIN category c ON p.category_id = c.category_id;

-- 三表：明细 → 订单、商品
FROM order_item i
JOIN orders  o ON i.order_id   = o.order_id
JOIN product p ON i.product_id = p.product_id
```
- n 张表要写 **n − 1 个**连接条件

## 连接以后再分组：各类别销售额
| 类别 | 销售额 |
|---|---|
| 粮油米面 | 51407.60 |
| 早餐冲饮 | 32988.80 |
| 休闲零食 | 24489.00 |
| 乳制品 | 24005.60 |
| 日用百货 | 18340.30 |

::: notes
order_item 连 product 再连 category，按类别分组求 SUM(quantity * unit_price)，只算已完成订单。
:::

# 5.3 外连接

## 内连接会“丢”行
| 连接方式 | 行数 | 留下了谁 |
|---|---|---|
| 内连接 | 3 | 两边都对得上的 |
| 左外连接 | 5 | + 没下单的顾客 |
| 右外连接 | 5 | + 没登记顾客的订单 |
| 全外连接 | 7 | 两边都保留 |

## 动手：四种连接对比
!sim join-types
- 切换内、左、右、全连接
- 看哪些行连上、哪些填 NULL
- 试试忘写连接条件

## 左连接：找“没有”的数据
```sql
SELECT c.customer_id, c.name
FROM customer c
LEFT JOIN orders o ON c.customer_id = o.customer_id
WHERE o.order_id IS NULL;     -- 29 位顾客从没下过单
```
- MySQL 没有 FULL JOIN：**左连接 UNION 右连接**
- 右表的条件放 **ON** 里，放 WHERE 会变成内连接

# 5.4 自连接

## 自连接：员工和上级
```sql
SELECT e.name AS 员工, e.position AS 职位, m.name AS 上级
FROM employee e
LEFT JOIN employee m ON e.manager_id = m.employee_id;
```
- 同一张表起**两个别名**，当成两张表
- 店长没有上级，用左连接才能留下

# 5.5 子查询

## WHERE 中的子查询
```sql
-- 比平均价贵的商品
SELECT name, price FROM product
WHERE price > (SELECT AVG(price) FROM product);

-- 金卡会员的姓名
SELECT name FROM customer
WHERE customer_id IN (SELECT customer_id FROM member
                      WHERE level = '金卡');
```
- 单个值用 `=`、`>`；一列值用 `IN`

## 相关子查询与派生表
- **相关子查询**：内层用到外层的列
  - 每个类别里比本类平均价贵的商品
  - 外层每一行，内层执行一次
- `EXISTS`：只问“有没有”
- **派生表**：FROM 里的子查询，**必须起别名**
- NOT IN 遇到 NULL 会一行也查不出

## 连接还是子查询？
| 问题 | 用连接 | 用子查询 |
|---|---|---|
| 金卡会员姓名 | `JOIN member` | `IN (SELECT …)` |
| 没买过东西的顾客 | `LEFT JOIN … IS NULL` | `NOT EXISTS (…)` |

::: notes
结果要显示两张表的列，只能用连接；“找出满足某条件的行”，子查询更直观。MySQL 8 对两种写法优化得都不错。
:::

# 5.6 UNION 与 WITH

## UNION 和 WITH
- `UNION`：上下拼接两个查询结果，**去重**
- `UNION ALL`：不去重，更快
- 两边**列数相同、类型对应**
- `WITH t AS (…)`：给中间结果起名，一步一步写

```sql
WITH paid AS (SELECT * FROM orders WHERE status = '已完成')
SELECT pay_method, COUNT(*) FROM paid GROUP BY pay_method;
```

## 一步步写出复杂查询
- ① 答案要哪些**列**？在哪些表？
- ② 表之间怎么**连**？
- ③ 先连起来，看几行**中间结果**
- ④ 再加 WHERE、GROUP BY
- ⑤ 核对行数和合计
