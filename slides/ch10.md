# 10.1 MySQL 的安装与配置

## 安装与配置文件
- 下载 MSI 安装包，安装类型选 **Typical**
- 用 **MySQL Configurator** 设端口、root 口令、服务
- **root 口令一定要记住**
- 配置文件 **my.ini**：端口、字符集、数据目录
- 改了配置要**重启服务**才生效
- 查看当前值：`SHOW VARIABLES LIKE 'port';`

::: notes
编者环境的实测值：character_set_server = utf8mb4，collation_server = utf8mb4_0900_ai_ci，default_storage_engine = InnoDB，max_connections = 151，port = 3306。
:::

## 启动、停止与连接
| 操作 | Windows 命令（管理员） |
|---|---|
| 启动服务 | `net start MySQL84` |
| 停止服务 | `net stop MySQL84` |
| 命令行连接 | `mysql -u root -p` |
| 检查是否在运行 | `mysqladmin -u root -p ping` |

- 图形界面：Win + R 输入 `services.msc`

# 10.2 PostgreSQL 的安装与配置

## MySQL 和 PostgreSQL 对照
| 项目 | MySQL 8.4 | PostgreSQL 17 |
|---|---|---|
| 默认端口 | 3306 | 5432 |
| 超级管理员 | root | postgres |
| 命令行客户端 | mysql | psql |
| 主配置文件 | my.ini / my.cnf | postgresql.conf |
| 谁能从哪里登录 | 账号的“主机”部分 | pg_hba.conf |
| 逻辑备份工具 | mysqldump | pg_dump |

## psql 的常用命令
| psql | 作用 | MySQL 对应 |
|---|---|---|
| `\l` | 列出数据库 | `SHOW DATABASES;` |
| `\c shop` | 切换库 | `USE shop;` |
| `\dt` | 列出表 | `SHOW TABLES;` |
| `\d product` | 看表结构 | `DESC product;` |
| `\q` | 退出 | `exit` |

## SQL 写法的常见差异
| 写法 | MySQL 8.4 | PostgreSQL 17 |
|---|---|---|
| 自增编号 | `AUTO_INCREMENT` | `GENERATED … AS IDENTITY` |
| 日期格式化 | `DATE_FORMAT(t, '%Y-%m')` | `TO_CHAR(t, 'YYYY-MM')` |
| 整数相除 `7 / 2` | 3.5000 | 3 |
| `'abc' = 'ABC'` | 1（不区分大小写） | f（区分） |
| 名字加引号 | 反引号 | 双引号 |

::: notes
其他差异：MySQL 有 IFNULL，PostgreSQL 只有 COALESCE；MySQL 中 a || b 是“或”运算，PostgreSQL 中是字符串拼接；插入后取新编号，MySQL 用 LAST_INSERT_ID()，PostgreSQL 用 INSERT … RETURNING。以上结果都是编者在两种数据库上实测的。
:::

# 10.4 用户与权限

## 账号：用户名 @ 主机
| 账号写法 | 含义 |
|---|---|
| `'clerk'@'localhost'` | 只能在服务器本机登录 |
| `'clerk'@'192.168.1.%'` | 只能从店里局域网登录 |
| `'clerk'@'%'` | 可以从任何地址登录 |

- 用户名相同、主机不同，是**两个不同的账号**
- `CREATE USER 'clerk'@'%' IDENTIFIED BY 'Clerk#2026';`

## GRANT 授权，REVOKE 收回
```sql
GRANT ALL PRIVILEGES ON *.* TO 'dba'@'localhost';   -- 全局
GRANT SELECT ON shop.* TO 'report'@'%';             -- 库级
GRANT SELECT, INSERT ON shop.orders TO 'clerk'@'%'; -- 表级
GRANT SELECT (customer_id, name)
  ON shop.customer TO 'clerk'@'%';                  -- 列级
REVOKE INSERT ON shop.orders FROM 'clerk'@'%';
SHOW GRANTS FOR 'clerk'@'%';
```

## 角色：把权限打包
```sql
CREATE ROLE r_clerk;                                -- ① 建角色
GRANT SELECT ON shop.product TO r_clerk;            -- ② 权限给角色
GRANT SELECT, INSERT ON shop.orders TO r_clerk;
GRANT r_clerk TO 'clerk1'@'%', 'clerk2'@'%';        -- ③ 角色给账号
SET DEFAULT ROLE ALL TO 'clerk1'@'%', 'clerk2'@'%'; -- ④ 自动启用
```
- 新来一个收银员，只要第 ③④ 步

## 最小权限原则：按岗位分
| 岗位 | 角色 | 能做 | 不能做 |
|---|---|---|---|
| 老板 | r_boss | shop 库全部 | 动别的库、建账号 |
| 收银员 | r_clerk | 查商品，录订单 | 改价、删订单、看手机号 |
| 会计 | r_accountant | 查订单和销售视图 | 改数据、看顾客信息 |

::: notes
账号安全：强口令、输错锁定（FAILED_LOGIN_ATTEMPTS 3 PASSWORD_LOCK_TIME 1）、不共用账号、日常不用 root。PostgreSQL 中用户和角色是一回事：CREATE ROLE clerk LOGIN PASSWORD '…'，能登录的角色就是用户。
:::

# 10.5 备份与恢复

## 用 mysqldump 备份和恢复
```bash
mysqldump -u root -p --databases shop --routines --triggers --events ^
  --single-transaction > D:\backup\shop_20261101.sql

mysql -u root -p < D:\backup\shop_20261101.sql
```
- 在**命令提示符**里运行，不是在 mysql> 里
- 编者实测：备份文件 273 KB，删库恢复后行数一致

::: notes
--routines --triggers --events 同时备份第 9 章建的存储过程、触发器、事件；--single-transaction 在一个事务里读，不用停业。^ 是 Windows 的续行符。DBeaver 里右键库名“工具 → 转储数据库”也能做。恢复前后 lab10_2_check.sql 的结果：category 8、product 48、customer 200、orders 2501、order_item 5811。
:::

## 全量 + 二进制日志 = 时间点恢复
!mermaid 1
- binlog 记下**每一次修改**，8.4 默认开启
- 先还原全量备份，再**重放** binlog

::: notes
编者实测 log_bin 为 ON，binlog_expire_logs_seconds 为 2592000 秒，即保留 30 天。实验 10-2 选做部分：备份后新增订单 2502，删库，只用全量恢复时 2502 不见了，再用 mysqlbinlog 重放那一段，2502 回来了。PostgreSQL 用 pg_dump，备份文件不含 CREATE DATABASE，恢复前要先建空库。
:::

## 小店的备份策略
| 项目 | 做法 |
|---|---|
| 多久一次 | 每天打烊后全量；binlog 一直开着 |
| 保留多久 | 每天的留 30 天，每月 1 日的留 1 年 |
| 放在哪里 | 本机、移动硬盘、云盘（**3-2-1 原则**） |
| 怎么做 | 批处理 + Windows 任务计划程序 |
| 怎么验证 | **每月一次恢复演练** |

# 10.6 数据库安全

## SQL 注入：输入被当成了 SQL
```sql
-- 程序把输入直接拼进 SQL，有人输入  ' OR '1'='1
SELECT customer_id, name, phone
FROM customer
WHERE phone = '' OR '1'='1';     -- 200 位顾客全被查出
```
- 根本办法：**参数化查询**（第 11 章）
- 数据库这一侧：**最小权限**

## 层层上锁
- **网络**：端口不暴露在互联网，防火墙只放行收银机
- **账号**：强口令、不共用、不用 root
- **权限**：最小权限，视图和列级权限隔开
- **数据**：敏感数据加密、展示时脱敏
- **审计**：记录谁在什么时候做了什么

## 加密与脱敏
```sql
SELECT customer_id, name,
       CONCAT(LEFT(phone, 3), '****', RIGHT(phone, 4)) AS phone
FROM customer;                     -- 100****1779
SELECT HEX(AES_ENCRYPT('13800001234', @k));   -- 可逆加密
SELECT SHA2('Boss#2026', 256);                -- 口令只存摘要
```
- 脱敏视图授权给 r_clerk，原表不给

## 法律对数据库的要求
| 法律要求 | 数据库里的做法 |
|---|---|
| 防止未经授权的访问 | 每人一个账号、最小权限 |
| 合理确定操作权限 | 按岗位建角色，定期检查 |
| 加密、去标识化 | 敏感字段加密、脱敏 |
| 防止丢失 | 定期备份、恢复演练 |

::: notes
依据：《中华人民共和国数据安全法》（2021 年 9 月 1 日起施行）第二十一条数据分类分级、第二十七条全流程数据安全管理；《中华人民共和国个人信息保护法》（2021 年 11 月 1 日起施行）第二十八条敏感个人信息、第五十一条加密、去标识化和合理确定操作权限。
:::
