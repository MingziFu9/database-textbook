# 附录 E 设计文档模板

第 6、7 章的设计实验（如实验 6-3“社区图书角”）和以后工作中的小项目，都可以按这里的模板写设计文档。模板来自第 6 章的“数据库设计六个阶段”，只保留专科层次真正用得上的部分。

## E.1 数据库设计文档模板 { #e1 }

```text
《××× 数据库设计说明》          版本：V1.0    编写人：______    日期：______

一、项目概述
    1. 背景：给谁用、解决什么问题（两三句话）
    2. 用户和角色：哪些人会用，各自能做什么（如店长、收银员、会计）

二、需求分析
    1. 业务流程：用文字或流程图写出主要业务的步骤（6.2.2）
    2. 要记录的数据：每个流程步骤“要记下什么”
    3. 常用查询和统计：列出至少 5 个“老板会问的问题”
    4. 业务规则：如“一张订单至少有一件商品”“积分不能为负”

三、数据字典（按 E.2 的表格，每个数据项一行）

四、概念设计
    1. E-R 图（陈氏表示法或乌鸦脚表示法，注明联系类型 1:1 / 1:N / M:N）
    2. 实体和联系说明：每个实体的含义、主码；每个联系的类型和属性

五、逻辑设计
    1. 关系模式：表名（主码加下划线，外码注明参照哪张表）
    2. 范式检查：说明每张表满足 3NF；如果有意保留冗余（反规范化），写明原因（7.6）

六、物理设计
    1. 每张表的列、类型、约束（可直接贴 SHOW CREATE TABLE 的结果）
    2. 索引：建在哪些列上，对应哪个常用查询（8.3.3）
    3. 视图：给哪类用户用，隐藏了哪些列
    4. 账号与权限：每个角色授予哪些权限（10.4）

七、实施与测试
    1. 建表脚本文件名、测试数据的来源
    2. 测试记录：用第二部分的“常用查询”逐条测试，记下 SQL 和结果
    3. 违反约束的测试：故意插入不合规数据，记下报错

八、备份与维护
    备份方式、频率、保存位置（10.5.5）
```

## E.2 数据字典模板 { #e2 }

每个数据项一行。“来源”写清楚这个值由谁提供：系统自动生成、顾客填写、店员录入等。6.2.3 节有“网上订单”的填写示例。

| 数据项 | 含义 | 类型和长度 | 取值范围 / 规则 | 可空 | 默认值 | 来源 | 所在表 |
|---|---|---|---|---|---|---|---|
| | | | | | | | |
| | | | | | | | |
| | | | | | | | |

填写提示：

- “类型和长度”先写业务上的说法（整数、金额、日期、文字最多 20 个字），物理设计时再换成 MySQL 类型；
- 金额写“两位小数”，将来用 DECIMAL；编号、手机号这类不参与计算的写“文字”；
- “取值范围”写清楚枚举值（如“上午、下午、晚上”）、上下限（如“≥ 0”）和与别的项的关系（如“不早于下单日期”）。

## E.3 设计自查清单 { #e3 }

交设计文档前，逐条检查（对应 6.6 节“常见的设计错误”和第 7 章）：

| 序号 | 检查项 | 是 / 否 |
|---|---|---|
| 1 | 每张表都有主键，最好是短小的自动增长整数 | |
| 2 | 每一格只放一个值，没有“爱好：唱歌,跳舞”这样的列（1NF） | |
| 3 | 组合主键的表里，没有只依赖主键一部分的列（2NF） | |
| 4 | 非主键列之间没有“A 决定 B”的依赖（3NF） | |
| 5 | 多对多联系建了中间表，中间表的主键由两边的主键组成 | |
| 6 | 外键列的类型与被参照的主键完全一致 | |
| 7 | 金额用 DECIMAL，不用 FLOAT；手机号用 CHAR(11)，不用 INT | |
| 8 | 没有“订单金额”这类可以算出来的列；如果有，写明了保留的理由 | |
| 9 | 有“状态”的数据（订单、配送）列出了全部状态值 | |
| 10 | 敏感数据（手机号、身份证号）规定了谁能看、是否脱敏 | |
| 11 | 第二部分列出的每个常用查询，都能用设计好的表写出来 | |
| 12 | 表名、列名统一用小写英文加下划线，同一含义在各表中名字一致 | |

## E.4 实验报告模板 { #e4 }

```text
实验名称：实验 X-X ________________      姓名：______  学号：______  日期：______

一、实验目的（照抄教材即可）

二、实验环境
    数据库及版本（如 MySQL 8.4.13）：          客户端（如 DBeaver 25.x）：
    使用的库：shop / myshop / txshop ……

三、实验过程与结果
    按教材的实验步骤，每一步写：
    1. 执行的 SQL（复制粘贴，不要截图代码）
    2. 运行结果（截图或复制表格；行数多时写出行数和前几行）
    3. 与教材“运行结果”是否一致；不一致时写出原因

四、实验记录表（照教材的记录表填写）

五、遇到的问题和解决办法
    报错信息原文 → 原因 → 怎样解决（可参考附录 B.6）

六、思考与练习（回答教材的问题）

七、体会（两三句话：这个实验让你明白了什么）
```

评分参考：步骤完整、SQL 正确 50%；结果真实并与教材核对 20%；问题记录与分析 20%；思考题 10%。截图要能看清 SQL 和结果；直接抄教材结果、没有自己运行痕迹的，按未完成处理。
